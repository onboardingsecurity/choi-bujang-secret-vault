# 관제 대시보드 실행·확인 순서

금오산(화면 제목은 「케셰브」) 보호 현황 맨 위에 상태 카드 네 개와 점검 이력을 붙인 기록입니다. 코드는 `student/extension.mjs`의 「관제 대시보드」 구역에만 있고, 제공 파일(`public/`, `src/`)과 제출 묶음 도구는 바꾸지 않았습니다. 포장하지 않고 프로젝트 폴더에서 바로 실행합니다(`npm run bundle`은 실행하지 않았습니다).

## 기능 점검표 (한 장 요약)

앱은 새 폴더를 만들지 않고 기존 저장소의 `on-client` 폴더에서 `npm start`로 실행했습니다(macOS, Node v24.14.1, 2026-10-28). 아래 값은 이 PC에서 직접 확인한 것(화면 캡처와 서버 응답)이고, 포털 안내 화면의 「예시 화면 · 설명용 값」이 아닙니다.

| 핵심 기능 | 지금 되나 | 되는 것(확인 방법) | 아직 안 되는 것 |
| --- | --- | --- | --- |
| 1. 상태 카드 네 개(값마다 출처 표시) | 지금 됨 | 연결 상태·기기·세션·AI 연결·설치 패키지 카드가 「내 PC 실측」/「예시」/「확인 불가」와 함께 보임(기본 실행·예제 실행 캡처) | 실제 엔진이 준 값 표시(엔진 연결 없음) |
| 2. 점검 이력(응답 시간) | 지금 됨 | 「지금 점검」을 누를 때마다 응답 시간이 쌓이고 서버를 끄면 `응답 없음` 줄이 생김(캡처) | 엔진 사건의 시간별 추이(엔진 데이터 없음) |
| 3. 패키지 실측 | 지금 됨(범위 한정) | `package-lock.json`을 읽어 조회 제외 건수를 「내 PC 실측」으로 표시(`ON_PROJECT_DIRECTORY` 지정, 캡처) | OSV 취약점 조회와 「알려진 취약점이 확인된 패키지」 숫자(허용 목록이 비어 있어 조회 안 함) |

- 위험 알림·실제 접속 기록처럼 엔진이 있어야 보이는 기능은 이 앱에서 아직 안 됩니다. 연결 없음일 때는 「확인 불가」로 표시하며 정상으로 읽히게 하지 않습니다.
- 실행이 안 될 때: 새 폴더를 만들지 않고 오류 문구 전체를 그대로 복사해 확인합니다. macOS에는 PowerShell이 없어서 22단계 안내의 `start-alekov.ps1` 대신 `npm start`를 썼습니다.

## 값 옆의 표시

| 표시 | 뜻 |
| --- | --- |
| 내 PC 실측 | 이 PC에서 직접 잰 값. 로컬 서버 응답 시간, 서버가 「엔진 연결 없음」으로 답한 것, `package-lock.json`을 읽은 결과 |
| 예시 | 예제(`demo`) 자료나 설명용 값. 실제 조회 결과가 아님 |
| 실제 연결 응답 | 연결된 기존 엔진이나 게이트가 준 값. 이 PC에는 연결이 없어 지금은 나오지 않음 |
| 확인 불가 | 값을 얻지 못함. 정상이나 안전이라는 뜻이 아님 |

## 다시 만드는 순서

Windows는 기존 안내(`STUDENT_LAUNCH_GUIDE.md`)의 `start-alekov.ps1`을 그대로 씁니다. macOS처럼 PowerShell이 없으면 아래 `npm start`를 씁니다. 같은 서버가 같은 주소로 켜집니다.

1. `on-client` 폴더에서 문법을 확인합니다: `npm run check` → 아무 출력 없이 끝나면 정상입니다.
2. 기본 실행(연결 없음): `npm start` → 터미널에 `케셰브 연결 확인: http://127.0.0.1:5189`가 나옵니다.
3. 브라우저에서 `http://127.0.0.1:5189/` → 「보호 현황」 맨 위에 카드 네 개와 아래 「점검 이력」이 보입니다.
4. 끄려면 터미널에서 `Ctrl+C`. 예제로 보려면 `npm run demo`(같은 주소).

패키지 조회까지 이 PC 값으로 보려면 저장소 루트의 절대 경로를 환경변수로 줍니다(값은 그 터미널에서만 쓰입니다).

    ON_PROJECT_DIRECTORY="<저장소 루트 절대 경로>" npm start

## 화면에서 확인할 것

| 실행 | 화면에서 볼 곳 | 정상 결과 | 거부되어야 할 결과(이렇게 보이면 안 됨) |
| --- | --- | --- | --- |
| `npm start` | 연결 상태 카드 | 「연결 없음」 + 「내 PC 실측」, 응답 시간 ○○ ms + 「내 PC 실측」 | 「연결됨」, 또는 연결 없음인데 「실제 연결 응답」 표시 |
| `npm start` | 기기·세션, AI 연결 카드 | 값은 「확인 불가」, AI 연결은 「점검 전」 | 기기 0개, 세션 0개, 「정상」처럼 읽히는 값 |
| `npm start` | 설치 패키지 카드 | 「조회 준비 미완료」 + 「확인 불가」 | 「취약점 없음」 |
| `npm start` | 점검 이력의 「지금 점검」 | 누를 때마다 한 줄 추가(최대 12줄), 줄에 `서버 응답 · ENGINE_NOT_CONNECTED` | 누르지 않았는데 계속 늘어남(자동 반복 금지) |
| `npm run demo` | 카드 전체 | 사용자·기기·세션·기록 값에 「예시」, 맨 위 안내 「아래 카드의 … 값은 모두 예시입니다」 | 예제 값에 「실제 연결 응답」 또는 「내 PC 실측」 |
| `ON_PROJECT_DIRECTORY` 지정 | 설치 패키지 카드 | 「아직 조회 안 함」, 조회 제외 건수 + 「내 PC 실측」, 알려진 취약점 칸은 「조회 안 함」 | 취약점 0개로 읽히는 표시 |
| 서버를 끈 뒤 「지금 점검」 | 점검 이력 | 줄이 `응답 없음 · NETWORK_ERROR`로 빨갛게 추가됨 | 성공 줄이 추가됨 |

점검 이력은 이번 실행 중 로컬 서버(`/api/me`)에 보낸 요청의 응답 시간입니다. 화면을 닫으면 사라지고 파일에 저장하지 않으며, 엔진 사건의 시간별 추이가 아닙니다.

## 확인한 것과 못 한 것

- 실행함(2026-10-28, macOS, Node v24.14.1): `node --check`, 서버 `GET /`와 API 응답, 가짜 DOM에서 렌더 함수를 돌려 본 결과(기본 실행·예제 실행·`ON_PROJECT_DIRECTORY` 지정). 이 PC에서 나온 문구는 위 표와 같습니다.
- 학생 화면 캡처로 확인(2026-10-28 오후 10시경, macOS 브라우저, 캡처 5장):
  - `npm run check`와 `npm start`의 터미널 출력(`케셰브 연결 확인: http://127.0.0.1:5189`).
  - 기본 실행의 점검 이력: 「내 PC 실측」 표시, 1회(3 ms)에서 「지금 점검」 뒤 2회(최소 3 ms · 평균 4 ms · 최대 5 ms)로 늘고 `서버 응답 · ENGINE_NOT_CONNECTED`, 보안 기록은 「확인 불가」.
  - 예제 실행 전체 화면: 「보호 현황」 제목 바로 아래에 카드 네 개와 점검 이력이 놓이고, 사용자·기기·세션·기록 값에는 「예시」, AI 연결과 패키지 조회는 「확인 불가」, 응답 시간만 「내 PC 실측」으로 구별됨. 스타일(CSP 환경의 스크립트 지정)도 깨지지 않음.
  - 기본 실행의 카드 네 개(캡처 2장, 오후 10:11~10:12): 연결 방식 「연결 없음 / 내 PC 실측」, 응답 시간 「내 PC 실측」, 기기·세션·AI 연결·패키지 조회는 「확인 불가」, 카드 위에 제공 화면의 연결 없음 알림 5건이 그대로 보임.
  - 서버를 끈 뒤 「지금 점검」: 빨간 `응답 없음 · NETWORK_ERROR` 줄이 추가되고 요약에 「응답 없음 1회」가 나옴.
- 이 캡처에서 찾아 고친 것: 응답 없음 요청의 대기 시간이 응답 시간 최소·평균·최대에 섞이던 것을, 응답한 점검만으로 계산하도록 바꿨습니다. 고친 뒤 화면은 캡처 2장으로 확인했습니다(오후 10:27): 4회 모두 응답했을 때 「응답한 4회 … 응답 없음 0회」, 서버를 끈 뒤 한 번 더 누르자 「최근 5회 · 응답한 4회 … 응답 없음 1회」와 빨간 `응답 없음 · NETWORK_ERROR` 줄. 이때 최소·평균·최대 숫자는 두 화면이 같은데, 응답 없음 줄(5 ms)을 넣어도 반올림하면 같은 값이라서입니다. 그래서 「응답한 4회」(5회가 아님)라는 개수가 제외했다는 근거입니다.
  - `ON_PROJECT_DIRECTORY`에 저장소 루트를 주고 「설치 패키지 조회」를 누른 화면(캡처 2장): 제공 카드는 `NO_APPROVED_PACKAGES`·잠금 파일 버전 3·조회 제외 32건, 맨 위 「설치 패키지」 카드는 조회 상태 「아직 조회 안 함」, 조회 대상 패키지 0개, 조회 제외 32건이 「내 PC 실측」, 알려진 취약점 칸은 「조회 안 함 / 확인 불가」. 취약점 없음으로 읽히는 표시는 없음. 제공 카드의 `출처 …osv.dev` 줄은 이름표이며 OSV로 요청을 보내지 않았음.
- 창 너비 1200·900·600px로 본 화면 3장(오후 10:28, 학생이 알려 준 너비): 카드 네 개가 위 세 개 + 아래 한 개(설치 패키지)로 줄바꿈되고, 글자·배지가 카드 밖으로 넘치지 않으며 가로 스크롤은 캡처에 보이지 않음.
- 확인할 수 없는 것: 900·600px 캡처는 제공 CSS의 `body { min-width: 1024px; }`(`public/style.css` 31행) 때문에 실제로는 1024px 폭으로 그려진 화면이 축소되어 보인 것입니다(두 캡처에서 사이드바 비율이 같음). 그래서 이 앱에서는 카드가 2열·1열이 되는 더 좁은 폭을 만들 수 없고, 그 상태는 확인 대상이 아닙니다. 1024px 이상의 배치만 확인했습니다. 좁은 화면 지원은 제공 화면(`style.css`)을 고쳐야 하는 일이며 이번 범위 밖입니다.
- 미실행: 실제 엔진 연결, AI 연결 성공, OSV 취약점 조회(승인 목록이 비어 있음), Windows에서의 실행, ALEPH 제출.
