# 관제 대시보드 실행·확인 순서

금오산(화면 제목은 「케셰브」) 보호 현황 맨 위에 상태 카드 네 개와 점검 이력을 붙인 기록입니다. 1일차에는 코드가 `student/extension.mjs`의 「관제 대시보드」 구역에만 있었고 제공 파일(`public/`, `src/`)과 제출 묶음 도구는 바꾸지 않았습니다. 이후 2·3일차에 PC 값을 읽으려고 `public/app.js`(허용 경로 줄)와 `src/server.mjs`(읽기 전용 경로)에 줄을 더하고 `src/`에 새 파일 두 개(`pc-status.mjs`, `system-status.mjs`)를 만들었습니다(아래 각 절의 「제공 기능과 내가 바꾼 부분」 참고). 4일차에는 제공 파일을 바꾸지 않았고, 제출 묶음 도구는 지금도 바꾸지 않았습니다. 포장하지 않고 프로젝트 폴더에서 바로 실행합니다(`npm run bundle`은 실행하지 않았습니다).

> 4일차부터 「지금 점검」 버튼은 항목별 「다시 조회」로 바뀌었습니다. 1~3일차 절의 「지금 점검」은 「다시 조회」로 읽어 주세요(당시 화면의 이름을 그대로 둔 기록입니다).

## 기능 점검표 (한 장 요약)

앱은 새 폴더를 만들지 않고 기존 저장소의 `on-client` 폴더에서 `npm start`로 실행했습니다(1일차 기록은 macOS, Node v24.14.1, 2026-10-28이고, 2026-10-29부터는 이 Windows PC, Node v24.18.1에서 같은 폴더·같은 명령으로 실행했습니다). 아래 값은 이 PC에서 직접 확인한 것(화면 캡처와 서버 응답)이고, 포털 안내 화면의 「예시 화면 · 설명용 값」이 아닙니다.

| 핵심 기능 | 지금 되나 | 되는 것(확인 방법) | 아직 안 되는 것 |
| --- | --- | --- | --- |
| 1. 점검 이력(응답 시간) | 지금 됨 | 「다시 조회」를 누를 때마다 서버 응답 시간이 쌓이고, 서버를 끄면 `응답 없음` 줄과 실패 안내가 생김(학생 캡처) | 엔진 사건의 시간별 추이(엔진 데이터 없음) |
| 2. 내 PC 상태(CPU·메모리·디스크) | 지금 됨 | 값마다 잰 시각·단위·출처와 추이 비교가 보이고, CPU·메모리가 작업 관리자와 맞음(학생 캡처, 2026-10-29) | 디스크 남은 공간을 탐색기 화면과 맞춘 캡처(별개의 명령 `Get-PSDrive`로는 같은 값을 확인함), 관리자 권한이 필요한 값(쓰지 않음) |
| 3. PC 연결·방화벽·Windows 기록 | 지금 됨 | 네트워크·방화벽 켜짐·최근 24시간 경고·오류 건수(침해 탐지 아님 표시)가 Windows 화면과 맞고, `SDP 미연결`을 따로 표시(학생 캡처) | 실제 SDP 연결, 5000건이 실제로 쌓이는 PC의 한도 표시, 권한이 없는 PC의 실제 화면 |

- 맨 위 상태 카드 네 개는 핵심 3가지가 아니라 화면 틀입니다. 연결 상태·기기·세션·AI 연결·설치 패키지 카드가 「내 PC 실측」/「예시」/「확인 불가」와 함께 보입니다(기본 실행·예제 실행 캡처, 1일차 macOS). 실제 엔진이 준 값은 엔진 연결이 없어 표시되지 않습니다.
- 핵심 3가지를 바꾼 기록: 1일차(2026-10-28)에는 「상태 카드 네 개·점검 이력·패키지 실측」을 골랐습니다. 이후 2·3일차 기능을 더하면서 지금 화면의 핵심 3가지를 위 표로 바꿨습니다. 패키지 실측은 제공 「설치 패키지 조회」와 겹치고 OSV 조회는 허용 목록이 비어 있어 하지 않으므로 핵심에서 뺐고, 카드 안의 「설치 패키지」 표시로만 남아 있습니다. 1일차 때의 확인(1일차 macOS 캡처): `ON_PROJECT_DIRECTORY`를 줄 때 `package-lock.json`의 조회 제외 건수가 「내 PC 실측」으로 보였습니다.

- 위험 알림·실제 접속 기록처럼 엔진이 있어야 보이는 기능은 이 앱에서 아직 안 됩니다. 연결 없음일 때는 「확인 불가」로 표시하며 정상으로 읽히게 하지 않습니다.
- 실행이 안 될 때: 새 폴더를 만들지 않고 오류 문구 전체를 그대로 복사해 확인합니다. macOS에는 PowerShell이 없어서 22단계 안내의 `start-alekov.ps1` 대신 `npm start`를 썼습니다.

## 다시 만드는 순서

기존 안내(`STUDENT_LAUNCH_GUIDE.md`)의 `start-alekov.ps1`이나 아래 `npm start`를 씁니다. 같은 서버가 같은 주소로 켜집니다.

1. `on-client` 폴더에서 문법을 확인합니다: `npm run check` → 아무 출력 없이 끝나면 정상입니다.
2. 기본 실행(연결 없음): `npm start` → 터미널에 `케셰브 연결 확인: http://127.0.0.1:5189`가 나옵니다.
3. 브라우저에서 `http://127.0.0.1:5189/` → 「보호 현황」 맨 위에 카드 네 개와 아래 「점검 이력」이 보입니다.
4. 끄려면 터미널에서 `Ctrl+C`. 예제로 보려면 `npm run demo`(같은 주소).

패키지 조회까지 이 PC 값으로 보려면 저장소 루트의 절대 경로를 환경변수로 줍니다(값은 그 터미널에서만 쓰입니다).

    ON_PROJECT_DIRECTORY="<저장소 루트 절대 경로>" npm start

## 내 PC 상태 (CPU 사용률·메모리·디스크 남은 공간)

「보호 현황」의 「점검 이력」 아래에 「내 PC 상태」가 붙습니다. 값은 이 PC에서 「지금 점검」을 누를 때만 한 번 잽니다. 이 구역에는 예시 값이 없습니다. 예제 실행(`npm run demo`)에서도 이 값은 엔진 예제와 무관하게 이 PC에서 잰 실측입니다.

### 제공 기능과 내가 바꾼 부분

| 구분 | 내용 |
| --- | --- |

### 값마다 붙는 것

| 값 | 단위 | 읽는 방법(일반 권한) | 집계 범위 |
| --- | --- | --- | --- |
| CPU 사용률 | % | `os.cpus()`를 250 ms 간격으로 두 번 읽은 차이 | 전체 코어 평균, 잰 시각 직전 250 ms 구간 |
| 메모리 사용 | % 와 GiB | `os.totalmem()`, `os.freemem()` | OS가 보고한 여유 기준(사용 = 전체 − 여유). 캐시로 쓰는 메모리는 사용에 포함될 수 있어 작업 관리자와 다를 수 있음 |
| 디스크 남은 공간 | GiB | `fs.statfs()`의 일반 사용자 기준 남은 공간 | 앱이 실행 중인 폴더가 있는 디스크 한 곳 |

- 값마다 **잰 시각**(이 PC의 시각)과 출처(함수 이름), 집계 범위가 옆에 붙습니다.
- 이 구역(CPU·메모리·디스크)은 관리자 권한이 필요한 방법, 외부 프로그램 실행, 셸 명령을 쓰지 않습니다(아래 「PC 연결·방화벽·Windows 기록」 구역은 읽기 전용 PowerShell 명령을 씁니다). 응답에는 컴퓨터 이름·사용자 이름·폴더 경로가 없습니다.
- 서버는 이 PC의 `127.0.0.1`에서만 열리고(코드에 고정, 바꾸는 설정 없음), 허용 Host도 `127.0.0.1`·`localhost`뿐입니다. **이 서버를 이 PC 밖에서 접속되게 열지 마세요**(배포, 포트 포워딩, 터널 등). 인증이 없어서 같은 서버의 다른 경로(`/api/actions/execute`, `/api/ai/explain`, `/api/events` 등)까지 함께 노출됩니다. 다른 컴퓨터에서 직접 받아 `npm start`로 로컬에서 돌리는 것은 괜찮습니다(그 컴퓨터의 값이 그 컴퓨터에만 보임). 이 앱은 Vercel 배포 대상이 아닙니다(`vercel.json`은 루트 `public`만 배포).

- 추이 비교: 최근 12회를 표로 쌓고 값마다 직전 점검 대비 증감(`▲ +3.1 %p`, `▼ −0.4 GiB`)을 붙입니다. 직전 값을 읽지 못했으면 증감을 계산하지 않고 이유를 적습니다. 화면을 닫으면 사라지고 파일로 저장하지 않습니다.

- 실제 명령으로 확인(2026-10-29, 코딩 도구가 실행, 읽기만 함): 권한 없는 Security 로그가 `PERMISSION_DENIED`로 나옴(일반 권한 계정). 세는 한도를 1건으로 낮추면 실제 `Get-WinEvent`에서 `capped:true`가 나오고 건수가 2건에서 멈춤. 이것은 한도를 낮춰 확인한 것이며 5000건이 실제로 쌓인 PC에서 본 것은 아닙니다.
- 점검 범위 밖으로 둔 것(지금은 할 수 없음): 실제 SDP 연결 상태. 개인 인증서·키·토큰을 담당자가 안내한 경로로 준비해야 하고(`docs/SDP_HOST_CONNECTION.md`), 이 앱은 연결 없음으로만 확인했습니다.
- 미확인: 5000건이 실제로 쌓이는 PC에서의 「한도에서 멈춤」 표시(한도를 낮춘 실제 명령 확인과 가짜 화면 시험까지만), 실제 SDP 연결 상태(엔진 연결 없음), ALEPH 제출과 판정(`npm run bundle`은 실행하지 않음).

## 4일차: 핵심 기능 3가지, 다시 조회, 오류 화면, 키보드 사용

화면 틀은 그대로입니다. 맨 위 상태 카드 네 개 아래에 「핵심 기능 3가지」 줄이 붙고, 학생이 더한 세 기능(점검 이력, 내 PC 상태, PC 연결·방화벽·Windows 기록)에 각각 「다시 조회」 버튼이 생겼습니다. 이전 절의 「지금 점검」 버튼은 「다시 조회」로 바뀌었고, 전체를 한 번에 읽는 버튼은 없습니다(제공 화면의 「다시 불러오기」와 겹치지 않게). 포장 명령(`npm run bundle`)은 실행하지 않습니다.

| 이전 일차에서 이미 바뀐 제공 파일 | `public/app.js`와 `src/server.mjs`에 학생 코드가 부를 수 있는 경로 줄을 더했고(이전 일차 `93fd7b0`, 3일차 `61296a5`), `src/`에 새 파일 두 개(`pc-status.mjs`, `system-status.mjs`)를 만들었습니다. 4일차에서는 더 바꾸지 않았습니다. 이 파일들을 되돌리면 「내 PC 상태」와 「PC 연결·방화벽·Windows 기록」이 서버에 닿지 못해 멈춥니다 |

### 핵심 기능 3가지와 「다시 조회」

| # | 기능 | 「다시 조회」가 하는 일 | 제공 화면과 겹침 |
| --- | --- | --- | --- |
| 1 | 점검 이력 | 로컬 서버(/api/me)의 응답 시간을 한 번 잼 | 없음(제공 「다시 불러오기」는 전체 상태를 다시 불러옴) |
| 2 | 내 PC 상태 | CPU·메모리·디스크 남은 공간을 한 번 읽음 | 없음 |
| 3 | PC 연결·방화벽·Windows 기록 | 네트워크·방화벽 켜짐·최근 24시간 경고·오류 건수를 읽기만 함 | 없음 |

제공 화면의 「다시 불러오기」, 「AI 연결 점검」, 「설치 패키지 조회」는 새로 만들지 않고 그대로 둡니다.

- **대기 표시**: 읽는 동안 구역 제목 옆에 「새로 읽는 중…」이 보입니다. 다른 조회가 아직 끝나지 않았으면 「대기 중 · 앞의 조회가 끝나면 읽습니다」로 줄을 섭니다. 세 조회는 한 번에 하나씩만 실행합니다(CPU 측정 중에 PowerShell이 돌면 CPU 값이 부풀려지는 결함을 3일차에 고쳤고, 그 순서를 지킵니다).
- **중복 누름**: 읽는 중에 같은 버튼을 다시 눌러도 조회는 한 번만 실행됩니다.
- **자동 반복 없음**: 화면을 처음 열 때 한 번씩, 그리고 「다시 조회」를 누를 때만 읽습니다.
- **성공**: 「성공 · 잰 시각 …」이 핵심 3가지 줄과 구역 머리에 보이고, 값마다 잰 시각·집계 범위·출처는 이전과 같습니다.
- **실패**: 실패한 항목 이름과 이유, 「다음에 할 일」이 담긴 빨간 상자가 보입니다. 이전 값이나 예시 값으로 채우지 않고, 값 자리는 「확인 불가」입니다. 일부 항목만 실패하면(예: Windows Application 기록만 권한 없음) 그 항목만 실패로 적고 나머지는 값과 잰 시각이 그대로 보입니다.
- **「내 PC 실측」과 「예시」 구분**: 이 세 구역에는 예시 값이 없습니다. 값은 모두 「내 PC 실측」 또는 「확인 불가」이고, 예제 실행(`npm run demo`)에서만 맨 위 카드와 SDP 줄에 「예시」가 붙습니다(이전 절과 같음). 이 문서에 쓴 숫자는 모두 이 PC에서 읽은 값이며 설명용 값이 아닙니다.

### 실패 때 「다음에 할 일」 (이유 코드별)

| 이유 | 화면에 나오는 다음에 할 일 |
| --- | --- |
| `NETWORK_ERROR`(서버가 응답 없음) | 터미널에서 서버(`npm start`)가 켜져 있는지 확인, 꺼졌으면 다시 켠 뒤 「다시 조회」 |
| `TIMEOUT` | 잠시 뒤 「다시 조회」, 계속되면 서버를 끄고 다시 켜기 |
| `NOT_FOUND`(옛 서버) | 서버를 끄고 다시 켠 뒤 「다시 조회」 |
| `PERMISSION_DENIED` | 일반 권한으로 읽을 수 없는 항목, 관리자 권한은 쓰지 않으니 「확인 불가」로 두고 나머지를 확인 |
| `UNSUPPORTED_OS` | Windows PC에서만 읽는 항목, Windows PC에서 서버를 켜고 「다시 조회」 |
| `COMMAND_UNAVAILABLE` | Windows PowerShell을 찾지 못함, Windows가 정상인지 확인 |
| `INVALID_RESPONSE`·`OUTPUT_INVALID` | 이상한 값이라 쓰지 않음, 한 번 더 조회하고 같으면 서버를 끄고 다시 켜기 |
| 그 밖(`UNREADABLE` 등) | 「다시 조회」를 눌러 보고, 계속되면 「확인 불가」로 기록 |

### 키보드만으로 쓰기

- 조작 요소는 모두 기본 버튼이라 `Tab`으로 이동하고 `Enter` 또는 `Space`로 누릅니다. 양수 `tabindex`는 쓰지 않았습니다.
- 「핵심 기능 3가지」 줄의 「바로 가기」 버튼은 해당 구역 제목으로 초점을 옮깁니다.
- 읽는 중에도 「다시 조회」 버튼은 `disabled`가 아니라 `aria-disabled`라서 초점이 사라지지 않고, 화면이 다시 그려져도 같은 버튼에 초점이 돌아옵니다.
- 「새로 읽는 중」·성공·실패 결과는 화면 맨 앞의 알림 자리(`role="status"`, `aria-live="polite"`)가 읽어 줍니다. 구역에는 읽는 중임을 알리는 `aria-busy`가 붙고, 추이 표에는 이름과 열 머리(`scope="col"`)가 붙습니다.
- 키보드 초점 표시(노란 테두리)는 제공 `style.css`의 것을 그대로 씁니다.

### 다시 만드는 순서

`on-client` 폴더의 PowerShell에서 실행합니다.

1. 문법 확인: `npm run check` → 출력 없이 끝나면 정상입니다.
2. 켜져 있는 서버가 있으면 `Ctrl+C`로 끄고 `npm start`를 실행합니다. 터미널에 `케셰브 연결 확인: http://127.0.0.1:5189`가 나오면 정상입니다. 화면 코드(`student/extension.mjs`)가 바뀌었으므로 브라우저도 새로 고칩니다.
3. 브라우저에서 `http://127.0.0.1:5189/`를 엽니다. 상태 카드 네 개 바로 아래에 「핵심 기능 3가지」 줄이 보여야 합니다.
4. 키보드로 `Tab`을 눌러 「1. 점검 이력 바로 가기」에서 `Enter`를 누르면 점검 이력 구역으로 이동합니다. 이어서 `Tab`으로 구역의 「다시 조회」에 가서 `Enter` 또는 `Space`를 누릅니다.
5. 실패 화면 만들기(공격이 아니라 서버를 끄는 것뿐입니다): 화면을 연 채로 서버 터미널에서 `Ctrl+C`를 눌러 서버를 끕니다. 「내 PC 상태」의 「다시 조회」를 누릅니다.
6. 서버를 다시 켜(`npm start`) 화면을 새로 고치지 않고 같은 「다시 조회」를 누르면 성공으로 돌아옵니다. 화면을 새로 고쳤다면 처음 상태로 돌아가 있어도 정상입니다.
