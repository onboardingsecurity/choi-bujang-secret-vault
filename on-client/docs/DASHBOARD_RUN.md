# 관제 대시보드 실행·확인 순서

금오산(화면 제목은 「케셰브」) 보호 현황 맨 위에 상태 카드 네 개와 점검 이력을 붙인 기록입니다. 코드는 `student/extension.mjs`의 「관제 대시보드」 구역에만 있고, 제공 파일(`public/`, `src/`)과 제출 묶음 도구는 바꾸지 않았습니다. 포장하지 않고 프로젝트 폴더에서 바로 실행합니다(`npm run bundle`은 실행하지 않았습니다).

## 기능 점검표 (한 장 요약)

앱은 새 폴더를 만들지 않고 기존 저장소의 `on-client` 폴더에서 `npm start`로 실행했습니다(macOS, Node v24.14.1, 2026-10-28). 아래 값은 이 PC에서 직접 확인한 것(화면 캡처와 서버 응답)이고, 포털 안내 화면의 「예시 화면 · 설명용 값」이 아닙니다.

| 핵심 기능 | 지금 되나 | 되는 것(확인 방법) | 아직 안 되는 것 |
| --- | --- | --- | --- |
| 1. 상태 카드 네 개(값마다 출처 표시) | 지금 됨 | 연결 상태·기기·세션·AI 연결·설치 패키지 카드가 「내 PC 실측」/「예시」/「확인 불가」와 함께 보임(기본 실행·예제 실행 캡처) | 실제 엔진이 준 값 표시(엔진 연결 없음) |
| 2. 점검 이력(응답 시간) | 지금 됨 | 「지금 점검」을 누를 때마다 응답 시간이 쌓이고 서버를 끄면 `응답 없음` 줄이 생김(캡처) | 엔진 사건의 시간별 추이(엔진 데이터 없음) |
| 3. 패키지 실측 | 지금 됨(범위 한정) | `package-lock.json`을 읽어 조회 제외 건수를 「내 PC 실측」으로 표시(`ON_PROJECT_DIRECTORY` 지정, 캡처) | OSV 취약점 조회와 「알려진 취약점이 확인된 패키지」 숫자(허용 목록이 비어 있어 조회 안 함) |

- 위험 알림·실제 접속 기록처럼 엔진이 있어야 보이는 기능은 이 앱에서 아직 안 됩니다. 연결 없음일 때는 「확인 불가」로 표시하며 정상으로 읽히게 하지 않습니다.
- 실행이 안 될 때: 새 폴더를 만들지 않고 오류 문구 전체를 그대로 복사해 확인합니다. macOS에는 PowerShell이 없어서 22단계 안내의 `start-alekov.ps1` 대신 `npm start`를 썼습니다.

## 값 옆의 표시

| 표시 | 뜻 |
| --- | --- |
| 내 PC 실측 | 이 PC에서 직접 잰 값. 로컬 서버 응답 시간, 서버가 「엔진 연결 없음」으로 답한 것, `package-lock.json`을 읽은 결과 |
| 예시 | 예제(`demo`) 자료나 설명용 값. 실제 조회 결과가 아님 |
| 실제 연결 응답 | 연결된 기존 엔진이나 게이트가 준 값. 이 PC에는 연결이 없어 지금은 나오지 않음 |
| 확인 불가 | 값을 얻지 못함. 정상이나 안전이라는 뜻이 아님 |

## 다시 만드는 순서

Windows는 기존 안내(`STUDENT_LAUNCH_GUIDE.md`)의 `start-alekov.ps1`을 그대로 씁니다. macOS처럼 PowerShell이 없으면 아래 `npm start`를 씁니다. 같은 서버가 같은 주소로 켜집니다.

1. `on-client` 폴더에서 문법을 확인합니다: `npm run check` → 아무 출력 없이 끝나면 정상입니다.
2. 기본 실행(연결 없음): `npm start` → 터미널에 `케셰브 연결 확인: http://127.0.0.1:5189`가 나옵니다.
3. 브라우저에서 `http://127.0.0.1:5189/` → 「보호 현황」 맨 위에 카드 네 개와 아래 「점검 이력」이 보입니다.
4. 끄려면 터미널에서 `Ctrl+C`. 예제로 보려면 `npm run demo`(같은 주소).

패키지 조회까지 이 PC 값으로 보려면 저장소 루트의 절대 경로를 환경변수로 줍니다(값은 그 터미널에서만 쓰입니다).

    ON_PROJECT_DIRECTORY="<저장소 루트 절대 경로>" npm start

점검 이력은 이번 실행 중 로컬 서버(`/api/me`)에 보낸 요청의 응답 시간입니다. 화면을 닫으면 사라지고 파일에 저장하지 않으며, 엔진 사건의 시간별 추이가 아닙니다.

## 내 PC 상태 (CPU 사용률·메모리·디스크 남은 공간)

「보호 현황」의 「점검 이력」 아래에 「내 PC 상태」가 붙습니다. 값은 이 PC에서 「지금 점검」을 누를 때만 한 번 잽니다. 이 구역에는 예시 값이 없습니다. 예제 실행(`npm run demo`)에서도 이 값은 엔진 예제와 무관하게 이 PC에서 잰 실측입니다.

### 제공 기능과 내가 바꾼 부분

| 구분 | 내용 |
| --- | --- |
| 제공 | 「기기·세션」 카드와 `/api/devices`의 **기기 보안 기준 상태**(충족·미충족·확인 불가). CPU·메모리·디스크 값은 아님. 코드 검색으로 제공된 「내 PC 상태」(CPU·메모리·디스크 측정)가 없음을 확인함 |
| 내가 바꾼 제공 파일 | `src/server.mjs`(가져오기 1줄과 `GET /api/pc-status` 경로 추가), `public/app.js`(학생 코드가 부를 수 있는 경로 목록에 `/api/pc-status` 한 개 추가) |
| 내가 만든 파일 | `src/pc-status.mjs`(측정), `student/extension.mjs`(「내 PC 상태」 표시와 추이 비교), 이 문서 |

### 값마다 붙는 것

| 값 | 단위 | 읽는 방법(일반 권한) | 집계 범위 |
| --- | --- | --- | --- |
| CPU 사용률 | % | `os.cpus()`를 250 ms 간격으로 두 번 읽은 차이 | 전체 코어 평균, 잰 시각 직전 250 ms 구간 |
| 메모리 사용 | % 와 GiB | `os.totalmem()`, `os.freemem()` | OS가 보고한 여유 기준(사용 = 전체 − 여유). macOS는 비활성·캐시 메모리를 여유로 세지 않아 활동 모니터보다 크게 높게 나올 수 있음 |
| 디스크 남은 공간 | GiB | `fs.statfs()`의 일반 사용자 기준 남은 공간 | 앱이 실행 중인 폴더가 있는 디스크 한 곳 |

- 값마다 **잰 시각**(이 PC의 시각)과 출처(함수 이름), 집계 범위가 옆에 붙습니다.
- 관리자 권한이 필요한 방법, 외부 프로그램 실행, 셸 명령은 쓰지 않습니다. 응답에는 컴퓨터 이름·사용자 이름·폴더 경로가 없습니다.
- 읽지 못한 값은 숫자 없이 「확인 불가」와 이유(권한 없음, 서버 연결 불가, 옛 서버, 응답 형식 오류 등)를 보입니다. 다른 값이나 이전 값으로 채우지 않습니다.
- 추이 비교: 최근 12회를 표로 쌓고 값마다 직전 점검 대비 증감(`▲ +3.1 %p`, `▼ −0.4 GiB`)을 붙입니다. 직전 값을 읽지 못했으면 증감을 계산하지 않고 이유를 적습니다. 화면을 닫으면 사라지고 파일로 저장하지 않습니다.

### 코드 위치와 조회 경로

- 브라우저 `student/extension.mjs`의 `measurePc()` → `GET /api/pc-status`(`public/app.js`의 허용 경로) → `src/server.mjs`의 `/api/pc-status` 처리 → `src/pc-status.mjs`의 `readPcStatus()`.
- 측정은 「지금 점검」을 누를 때와 화면을 처음 열 때 한 번씩만 일어나고, 자동으로 반복하지 않습니다.

### 다시 만드는 순서

`on-client` 폴더에서 실행합니다. 새 경로는 서버를 다시 켜야 생깁니다.

1. 문법 확인: `npm run check` → 출력 없이 끝나면 정상입니다.
2. 켜져 있는 서버가 있으면 `Ctrl+C`로 끄고 `npm start`를 실행합니다(macOS는 PowerShell이 없어 `npm start`, Windows는 기존 `start-alekov.ps1`도 됩니다).
3. 터미널에서 서버 응답 확인: `curl -s http://127.0.0.1:5189/api/pc-status` → `cpu`·`memory`·`disk` 모두 `"status":"ok"`이고 값마다 `measuredAt`(잰 시각)·`scope`(집계 범위)·`source`(출처)가 있으며 컴퓨터 이름·사용자 이름·경로는 없으면 정상입니다. 단위는 `cpu`는 `unit`(`%`) 필드에, `memory`·`disk`는 필드 이름(`usedPercent`는 %, `usedGiB`·`freeGiB`·`totalGiB`는 GiB)에 들어 있습니다. 세 값의 `measuredAt`은 서로 다를 수 있습니다(CPU는 250 ms 구간이 끝난 시각).
4. 브라우저에서 `http://127.0.0.1:5189/` → 「보호 현황」 → 「점검 이력」 아래 「내 PC 상태」 → 「지금 점검」을 두세 번 누릅니다.
