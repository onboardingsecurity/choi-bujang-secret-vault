# 금오산 완성본: 시연 순서와 정리

금오산(화면 제목은 「케셰브」)은 이 PC 안에서만 켜지는 보호 현황 화면입니다. 이 문서는 ① 제공 기능과 내가 만든 기능, ② 핵심 기능 3가지를 보여 주는 시연 순서, ③ 아직 안 되거나 「확인 불가」로 남은 한계, ④ 실제로 확인한 근거, ⑤ 같은 결과를 다시 만드는 명령을 나눠 적습니다. 확인하지 않은 것은 된다고 쓰지 않았습니다. 일차별 상세 기록은 `docs/DASHBOARD_RUN.md`에 있습니다.

## 값 옆의 표시

| 표시 | 뜻 |
| --- | --- |
| 내 PC 실측 | 이 PC에서 직접 잰 값 |
| 예시 | 설명용 값(예제 실행 `npm run demo`의 사용자·기기·세션·기록 값). 실제 조회 결과가 아님 |
| 실제 연결 응답 | 연결된 엔진이 준 값. 이 PC에는 연결이 없어 나오지 않음 |
| 확인 불가 | 값을 얻지 못함. 정상이나 안전이라는 뜻이 아님 |

핵심 기능 3가지의 값은 모두 「내 PC 실측」이고, 예제 실행(`npm run demo`)에서도 예시 값이 섞이지 않습니다. 이 문서에 적힌 숫자는 그날 그 PC에서 잰 값의 기록이며, 다시 실행하면 다릅니다.

## 1. 제공 기능과 내가 만든 기능

| 구분 | 내용 |
| --- | --- |
| 제공 | 서버(`src/server.mjs`와 `src/` 아래 제공 파일), 화면 틀(`public/`), 「연결 상태」·「기기·세션」 카드, 제공 버튼 「다시 불러오기」·「AI 연결 점검」·「설치 패키지 조회」, 기존 경로(`/api/me`, `/api/devices` 등). 22단계까지 내가 만든 화면 함수도 `student/extension.mjs`에 그대로 있습니다 |
| 내가 만든 것(총공세) | `student/extension.mjs`의 관제 대시보드(맨 위 상태 카드 네 개, 「핵심 기능 3가지」 줄, 점검 이력, 내 PC 상태, PC 연결·방화벽·Windows 기록, 「다시 조회」·대기 표시·실패 안내·키보드 사용), `src/pc-status.mjs`(CPU·메모리·디스크 읽기), `src/system-status.mjs`(네트워크·방화벽·Windows 기록 읽기), `test/system-status.test.mjs`(시험 12개), `docs/DASHBOARD_RUN.md`, 이 문서 |
| 내가 바꾼 제공 파일 | `public/app.js`(학생 코드가 부를 수 있는 경로 목록에 `/api/pc-status`, `/api/system-status` 추가, 1줄 변경), `src/server.mjs`(두 읽기 전용 경로와 가져오기, 12줄 추가). 이 두 파일을 되돌리면 「내 PC 상태」와 「PC 연결·방화벽·Windows 기록」이 서버에 닿지 못해 멈춥니다 |
| 건드리지 않은 것 | `public/style.css`, `public/index.html`, `package.json`, 제출 묶음 도구, 21·22단계 제출물(`STUDENT_RUNBOOK.md`, `STUDENT_REPRODUCTION.md`) |

제공 파일을 바꾼 것에 대한 판단은 아래 「4. 확인한 근거」의 「학생 판단」에 적었습니다.

## 2. 핵심 기능 3가지와 시연 순서

핵심 3가지는 ① 점검 이력, ② 내 PC 상태, ③ PC 연결·방화벽·Windows 기록입니다(화면의 「핵심 기능 3가지」 줄과 같은 이름·순서). 모두 읽기만 하며 PC 설정을 바꾸지 않습니다.

시작: `on-client` 폴더에서 `npm start` → 브라우저에서 `http://127.0.0.1:5189/`를 엽니다. 「보호 현황」 맨 위에 카드 네 개와 「핵심 기능 3가지」 줄이 보여야 합니다.

| 순서 | 보여 줄 것 | 누를 곳 | 정상 결과 | 이렇게 보이면 안 됨 |
| --- | --- | --- | --- | --- |
| 1 | 점검 이력 | 「핵심 기능 3가지」 줄의 「1. 점검 이력 바로 가기」 → 구역의 「다시 조회」를 두세 번 | 누를 때마다 한 줄이 쌓이고 `서버 응답 · ENGINE_NOT_CONNECTED`, 응답 시간(ms)과 「내 PC 실측」이 붙음 | 누르지 않았는데 줄이 늘어남 |
| 2 | 내 PC 상태 | 「내 PC 상태」의 「다시 조회」를 두세 번 | CPU 사용률·메모리 사용·디스크 남은 공간에 단위, 잰 시각, 집계 범위, 출처, 「내 PC 실측」이 붙고, 추이 표에 직전 대비 증감이 쌓임 | 시각이나 단위가 없는 값, 「예시」가 붙은 값 |
| 3 | PC 연결·방화벽·Windows 기록 | 「PC 연결·방화벽·Windows 기록」의 「다시 조회」를 두세 번 | `유선 N/M 연결 · 무선 N/M 연결`, `도메인·개인·공용 켜짐` 또는 꺼짐, System·Application의 `오류 N건 · 경고 N건`(최근 24시간), 「침해나 공격을 탐지한 결과가 아닙니다」 문구, `SDP 미연결`이 따로 한 줄 | IP·MAC·컴퓨터 이름이 보임, 설정을 바꾸는 버튼, 읽지 못했는데 0건으로 보임 |
| 4 | 실패 화면(선택) | 서버를 켠 터미널에서 `Ctrl+C`로 끈 뒤 「내 PC 상태」의 「다시 조회」 | 「조회에 실패한 항목」, 이유(로컬 서버에 연결할 수 없습니다), 「다음에 할 일」, 값 자리는 「확인 불가」 | 이전 숫자나 예시 값이 대신 보임, 실패인데 「성공」으로 보임 |
| 5 | 복구(선택) | 서버를 다시 켜(`npm start`) 화면을 새로 고치지 않고 같은 「다시 조회」 | 실패 상자가 사라지고 「마지막 조회 성공 · 잰 시각」 | 실패 상자가 계속 남음 |

예제 실행(`npm run demo`)을 보여 주려면 서버를 끄고 `npm run demo`로 다시 켭니다. 위 카드의 사용자·기기·세션·기록 값에는 「예시」가 붙고, 핵심 3가지의 값은 그대로 「내 PC 실측」입니다. `npm start`와 `npm run demo`는 같은 포트(5189)를 써서 한 번에 하나만 켤 수 있습니다.

## 3. 한계: 아직 안 되거나 「확인 불가」로 남은 것

| 항목 | 지금 할 수 있나 | 이유 | 누가 |
| --- | --- | --- | --- |
| 실제 SDP 연결 상태 | 할 수 없음 | 엔진 연결이 없습니다. 연결하려면 담당자가 안내한 경로로 인증서·키·토큰을 준비해야 하는데(`docs/SDP_HOST_CONNECTION.md`), 비밀값은 이 앱이나 대화, 저장소에 넣지 않습니다. 화면에는 `SDP 미연결`로 보입니다 | 담당자(운영 측) |
| 위험 알림, 실제 접속 기록, 기기·세션 값, AI 연결 성공 | 할 수 없음 | 엔진이 줘야 보이는 값이고 엔진 연결이 없습니다. 화면에는 「확인 불가」(AI 연결은 「점검 전」)로 보이며 정상으로 읽히지 않게 했습니다 | 담당자(운영 측) |
| 5000건이 실제로 쌓이는 PC의 「한도에서 멈춤」 표시 | 할 수 없음 | 이 PC의 최근 24시간 기록은 수십 건 이하라 한도에 닿지 않습니다. 대량으로 만들려면 PC의 기록을 오염시켜야 합니다. 한도를 낮춘 실제 명령 확인과 가짜 화면 시험까지만 했습니다 | - |
| 읽기 실패의 실제 화면(「권한 없음」, 디스크 읽기 불가) | 할 수 없음 | 이 PC에서는 일반 권한으로 모두 읽혀 실패가 생기지 않습니다. 일부러 만들려면 로그 접근 권한 같은 PC 설정을 바꿔야 하는데 이 앱은 설정을 바꾸지 않습니다. 가짜 응답 시험은 통과했고, 같은 실패 상자는 서버를 끈 실제 화면에서 확인했습니다 | - |
| 관리자 권한이 필요한 값(Security 로그 등) | 하지 않기로 함 | 일반 권한으로만 읽는 앱으로 정했습니다. 읽지 못하면 「확인 불가」로 둡니다 | - |
| 설치 패키지의 알려진 취약점 조회(OSV) | 하지 않기로 함 | 외부 조회 허용 목록이 비어 있고 제공 「설치 패키지 조회」와 겹쳐서 핵심에서 뺐습니다. OSV로 요청을 보낸 적이 없습니다 | - |
| 디스크 남은 공간과 탐색기 화면의 캡처 비교 | 할 수 있음(아직 안 함) | 앱 값은 앱과 별개의 Windows 명령 `Get-PSDrive`와 같음까지만 확인했습니다. 탐색기 캡처는 없습니다 | 학생 |
| Windows가 아닌 OS에서의 「PC 연결·방화벽·Windows 기록」 | 할 수 없음 | 이 구역은 Windows 전용이라 Windows가 아니면 「확인 불가 · Windows 전용」으로 나오게 했고, 가짜 화면 시험으로만 확인했습니다. 이 PC가 Windows라 실제로 돌려 보지 못했습니다 | - |
| 1024px보다 좁은 창 | 할 수 없음 | 제공 `public/style.css`의 `min-width: 1024px` 때문에 더 좁은 배치를 만들 수 없습니다. 고치려면 제공 화면을 고쳐야 합니다 | - |
| ALEPH 제출과 판정 | 아직 안 함 | 총공세 7일차까지 끝낸 뒤 한 번 제출하기로 했습니다. 판정은 ALEPH만 낼 수 있고, 이 문서는 판정을 대신하지 않습니다 | 학생 제출, ALEPH 판정 |

## 4. 확인한 근거

근거는 네 가지로 나눕니다. 날짜는 2026-10-28~30입니다.

### 4-1. 화면 캡처(학생이 찍어 보내 준 것)

| 기능 | 확인한 것 | 시점·환경 |
| --- | --- | --- |

### 4-3. 학생 직접 확인과 학생 판단(제가 본 것이 아닌 학생 보고)

- 학생 직접 확인: `Tab` 순서 전체, 스크린 리더(내레이터), 「대기 중」 줄서기, 다른 두 구역의 복구 화면(10-30)
- 학생 직접 확인: 이 문서의 시연 순서 1~5를 처음부터 끝까지 따라 실행했고, 화면이 문서의 정상 결과·한계 표시와 맞음(7일차, 10-30, 캡처는 4-1의 마지막 줄)
- 학생 직접 확인: 다른 사람이 이 문서(`DASHBOARD_RUN.md`)만 보고 `npm start`와 `npm run demo`를 차례로 실행했고 막힌 곳이 없었음(5일차, 10-30)
- 학생 직접 확인: GitHub 저장소 화면에서 제출할 커밋 번호 확인(6일차, 10-30)
- 학생 판단(통과로 처리): 제공 파일(`public/app.js`, `src/server.mjs`) 변경. 1~3일차 요구 글에는 제공 파일을 고치지 말라는 말이 없고, 「고치지 마」는 4일차 글에만 있으며 4일차에서는 제공 파일을 바꾸지 않았습니다. 코스 문서의 「제공 파일은 고치지 않습니다」는 13~22단계 과정의 규칙이며 총공세 부분에는 적용하지 않는다고 판단했습니다

## 5. 같은 결과를 다시 만드는 명령과 확인 순서

Windows PowerShell에서 합니다. 준비물은 Node.js 24와 Git입니다.

| 순서 | 명령 | 정상 결과 | 이렇게 보이면 안 됨 |
| --- | --- | --- | --- |
| 1 | `git clone https://github.com/onboardingsecurity/choi-bujang-secret-vault.git` 후 `cd choi-bujang-secret-vault\on-client` | `on-client` 폴더로 이동 | `fatal:`로 시작하는 줄 |
| 2 | `npm run check` | `> node --check student/extension.mjs` 같은 안내만 나오고 오류 글이 없음 | `Error`, `SyntaxError` |
| 3 | `node --test test/system-status.test.mjs` | `pass 12`, `fail 0` | `fail`이 1 이상 |

포장 명령(`npm run package-app`, `npm run bundle`)은 이 과정에서 실행하지 않았습니다.
