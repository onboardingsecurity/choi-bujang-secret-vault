# 금오산 새 환경 실행·재현 기록 (22단계)

이 문서는 학생이 새로 쓴 문서입니다. 제공 문서와 `STUDENT_RUNBOOK.md`(21단계)는 고치지 않았고, 이 문서가 그 내용을 대신하지도 않습니다. 코드는 바꾸지 않았습니다.

**이 기록의 성격.** 아래는 학생이 자기 PC의 새 폴더에서 직접 실행하고 화면을 본 기록(학생 진술과 화면 캡처)입니다. 서버가 새 환경에서 실행한 결과가 아니고, AI 원문 검토가 통과해도 실행 성공의 증명이 되지 않습니다. 예제(demo) 결과는 실제 연결 결과가 아닙니다.

| 표기 | 뜻 |

결과 칸의 값은 네 가지입니다. **재현됨**, **재현 안 됨**, **연결 없음**, **확인 불가**. 예제 자료로만 본 것과 연결 없음 상태에서 본 것은 「재현됨」으로 쓰지 않았습니다.

## 3. 절차 (새 폴더에서 같은 커밋 받기와 실행)

아래는 학생이 실행한 순서입니다. 기존 폴더의 설정·인증 파일은 복사하지 않았고, `npm install`은 필요하지 않았습니다(`on-client/package.json`에 의존성이 없음).

1. 새 빈 폴더를 만들고 저장소를 받습니다. `git clone` 끝의 `.`가 빠져 저장소가 `repro-22` 아래 `choi-bujang-secret-vault` 폴더로 들어갔습니다. 결과는 같아서 위치만 위 표에 적었습니다.

       git clone https://github.com/onboardingsecurity/choi-bujang-secret-vault.git
       git checkout --detach a918bc0cc8ddabc17910591eddac27050c3dcbe1
       git rev-parse HEAD
       git status --short

   `HEAD`가 위 40자리와 일치했고 `git status`는 출력이 없었습니다(학생 진술, 읽기 명령으로 같은 값을 다시 확인함).
2. `on-client`로 이동해 Node.js 버전을 확인하고 실행합니다.

       cd <새 폴더>\on-client
       node --version
       powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1

   창에 `참고: 지금 Node.js 는 v24.18.1 입니다. 수업 기준은 v24.19.0 입니다.`, `케셰브 연결 확인: http://127.0.0.1:5189`, `케셰브가 켜졌습니다…`, `서버가 응답한 것만 확인했습니다…`, `끄려면 이 창에서 Ctrl+C 를 누르세요.`가 차례로 나왔습니다(화면 캡처).
3. 브라우저에서 `http://127.0.0.1:5189`를 열어 13~20단계 화면을 눌러 봅니다(4장).
4. `Ctrl+C`로 끕니다. 브라우저에서 `ERR_CONNECTION_REFUSED`를 확인했습니다(화면 캡처).
5. 같은 명령으로 다시 켜서 같은 화면이 나오는지 봅니다(화면 캡처, 5장).
6. 끄고 `-Demo`를 붙여 켭니다.

       powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -Demo

   창에 `케셰브 예제: http://127.0.0.1:5189`가 나왔고(화면 캡처), 예제 자료 화면을 눌러 봅니다.
7. `Ctrl+C`로 끕니다. 브라우저에서 다시 `ERR_CONNECTION_REFUSED`를 확인했습니다(화면 캡처).

## 5. 끄고 다시 켠 뒤의 결과

재실행 뒤 화면은 같은 「연결 없음」으로 시작했고 사용자·기기·세션이 「확인 불가(요청 실패)」였으며 확인 시각은 새 값(오후 3:59:39)이었습니다(화면 캡처). 같은 명령으로 한 번 더 켠 실행(오후 4:23:41)에서는 AI 연결 칸이 「AI 연결 점검 전」, 패키지 조회 칸이 「조회 전」, 도움정보가 「아직 불러오지 않았습니다」로 시작했고 이전에 본 오류 코드(`AI_REQUEST_UNVERIFIED`, `PROJECT_NOT_CONFIGURED`)가 남아 있지 않았습니다(화면 캡처 4장). 재실행 때 PowerShell 창 출력은 세 번째 재실행(오후 4:29:32)에서 캡처로 확인했습니다. 앞의 두 재실행(오후 3:59:39, 4:23:41)은 창 출력 캡처가 없습니다. 세 번째 재실행의 창에는 `참고: 지금 Node.js 는 v24.18.1 입니다. 수업 기준은 v24.19.0 입니다.`, `케셰브 연결 확인: http://127.0.0.1:5189`, `케셰브가 켜졌습니다…`, `서버가 응답한 것만 확인했습니다…`, `끄려면 이 창에서 Ctrl+C 를 누르세요.`가 차례로 나왔고, 같은 시각 화면은 「연결 없음」이었습니다(화면 캡처).

## 6. 데이터 보존·백업·복원 계획

- **앱이 파일로 저장하는 학생 데이터:** `on-client/src/`와 `vendor/`에서 `writeFile`, `appendFile`, `createWriteStream`, `rename` 호출을 찾지 못했습니다(검색으로 확인, 코드만 읽음). 파일 접근 코드는 설정·프로젝트 파일을 읽고 검증하는 것이었습니다. 새 폴더에서 실행한 뒤에도 `git status`에 새 파일이 생기지 않았습니다(읽기 명령 확인).
- **보존할 것:** 학생이 만든 코드(`student/extension.mjs`)와 문서(`docs/STUDENT_RUNBOOK.md`, 이 문서)입니다. Git 커밋과 GitHub 원격 저장소가 보존·백업 수단입니다. 이 문서를 쓰기 전에 원격 `main`이 `a918bc0cc8ddabc17910591eddac27050c3dcbe1`과 같은 것을 확인했습니다(읽기 명령 확인).
- **복원 방법:** 새 빈 폴더에 `git clone`으로 받고 `git checkout --detach <40자리 커밋>`으로 같은 시점을 가져옵니다. 이번 새 폴더 실행이 그 절차의 실제 예입니다.
- **비밀·설정:** 설정 파일·인증서·열쇠는 프로젝트·Git·제출물 밖에 둡니다(제공 안내 `docs/FINAL_PRODUCT_GUIDE.md` 6장 기준). 새 폴더에 기존 폴더의 설정·인증 파일을 복사하지 않았습니다. 기본 실행과 `-Demo`에는 설정 파일이 필요하지 않았습니다.
- **제한:** 도움정보, 점검 결과, 조회 결과 같은 화면의 값을 앱이 파일로 보존하는지는 코드에서 파일 쓰기 호출을 찾지 못한 것 외에 확인하지 못했습니다. 이 문서에 옮겨 적은 값이 그 값들의 보존 수단은 아닙니다. 저장소 루트의 `backup/`과 `api/`는 1~12단계 자료실용이며 이 앱과는 별개입니다. 실제 연결을 붙였을 때의 데이터 보존은 이번에 다루지 못했습니다.

## 7. 이동 가능한 구성

- 필요한 것은 Git, Node.js 22~24(수업 기준 `v24.19.0`), PowerShell입니다. 외부 npm 패키지가 없습니다.
- 설치 절차는 3장입니다. 기본 실행과 `-Demo`에는 설정 파일 예시가 필요하지 않습니다. `.env.example`은 저장소에 없고(`.gitignore`의 `.env.*` 때문) 새 폴더 실행에도 필요하지 않았습니다.
- 학생 코드와 설명서에서 `C:\Users\…` 같은 로컬 절대경로는 찾지 못했습니다(검색, 코드만 읽음). 이 문서의 경로는 `<…>` 자리표시자로 적었습니다.
- 사용자 이름, 비밀번호, 토큰, API 키, 개인키는 이 문서와 코드에 넣지 않았습니다.

## 8. 시연·학생 진술·원문 확인·실제 실행의 구분

| 구분 | 이 기록에서 해당하는 것 |
| --- | --- |
| 시연(예제 자료) | `-Demo`로 본 13·14·15·18·19단계 화면. 실제 연결이 아님 |
| 학생 진술 | 다시 불러오기 뒤 시각이 바뀐 것, 새 폴더 `git clone` 직후 상태 |

## 9. 버전과 지원 범위, 남은 것 (기다림, UNV)

이 버전은 **검증 중인 버전**이고 v1.0이 아닙니다. 22단계 통과가 있더라도 원문 검토 기준의 수료이며 실제 운영 인증이나 v1.0 자동 인증이 아닙니다. v1.0은 19단계 실제 실행 연결과 22단계의 같은 최종 소스 누적 재현·공식 접수 연결이 완료·수용된 경우에만 붙입니다.

**지원하는 범위(이 기록으로 확인한 것):** 연결이 없을 때 정직하게 「연결 없음」·「확인 불가」로 표시하는 것, 예제 자료 화면, 종료·재실행.

**확인하지 못한 것:**

| 항목 | 이유 |
| --- | --- |
| 실제 회사 시스템에 연결된 모든 화면(13~16단계의 실제 값) | 연결 설정과 인증서가 없음. 연결 없음과 예제 자료만 확인 |
| 17단계 AI 연결 점검 성공 화면, 18단계 근거 있는 AI 설명 성공 화면 | 계정 연결·AI 앱 승인을 하지 않았고 권한이 준비되지 않음 |
| 19단계 조치 제안·접수·효과 확인, 실제 집행 | 예제 기록에 지원 조치가 없고 실제 집행 연결은 준비되지 않음 |
| 20단계 패키지 행·OSV 조회 결과 | 조회 대상 프로젝트 설정이 없음 |
| 15단계 기록 여러 건, 14단계 `unknown`·요청 실패 화면, 16단계 미지원 조치 안내 | 예제 자료가 기록 1건, 판정 3종, 조치 없음뿐 |
| 16단계 빈 화면(기기·세션이 0건인 상태) | 이 환경에서 만들지 못함. 오류 상태(연결 없음)와 예제 자료의 1건 상태만 확인함 |
| 17·18·15단계 일부의 확인 시각 | 캡처에 확인 시각이 없음 |
| Node.js `v24.19.0`에서의 실행, 다른 PC·운영체제·브라우저 | 하지 않음 |
| 13~21단계의 포털 판정 결과 | 학생이 알려 준 것이며 포털 화면은 확인하지 못함 |

## 11. 같은 최종 소스 확인 (문서를 커밋한 뒤)

이 문서만 추가한 커밋이라면 코드는 검증한 커밋과 같아야 합니다. 커밋 뒤 아래를 실행해 변경된 파일이 이 문서 하나인지 확인합니다. 아직 실행하지 않았습니다(미확인).

    git diff --stat a918bc0cc8ddabc17910591eddac27050c3dcbe1 HEAD

서로 다른 커밋의 통과 결과를 합쳐 최종 버전 전체의 성공으로 적지 않았습니다. 위 4장의 모든 결과는 `a918bc0cc8ddabc17910591eddac27050c3dcbe1` 한 커밋에서 얻은 것입니다.
