## 보너스: 몰래 심어진 프로그램 탐지 현재 상태

연습 경보(`xdr/fixtures/persistence.json`, 가상 24건)만 다루는 부품입니다. 서명 없는 새 서비스, 처음 보는 예약 작업, 시작 폴더 변경을 다룹니다. 앞의 세 보너스와 같은 구조이고, ZTNA 판정기(`src/decider.mjs`)에는 **연결하지 않았습니다**(아래). 이 결과는 직접 돌린 연습이며 심판 판정이 아닙니다. 판정기의 기존 규칙과 `RULE_IDS` 5개는 바꾸지 않았습니다.

- `xdr/persistence/decide.mjs`: `decide(alert)` 하나만 내보내며 `import`가 없고 파일·네트워크·시계도 쓰지 않습니다. 반환은 `{ action, confidence, reason }`이고 0.85 이상 block, 0.5 이상 alert, 그 아래 record입니다. `reason`은 근거 패턴 이름으로 시작합니다. 경보 설명 문장과 실행 파일 경로(`data.path`)의 모양만 읽고, `reason`에는 경로·설명 원문을 옮겨 적지 않습니다.
- `xdr/persistence/patterns.json`: 근거 패턴 셋(`unsigned_new_service` T1543.003, `unfamiliar_scheduled_task` T1053.005, `startup_folder_change` T1547.001)입니다. 시작 폴더는 연습 경보가 T1543으로 표시했지만 ATT&CK에서는 T1547.001이라 그 번호를 적었고, 경보의 `mitre` 칸은 읽지 않습니다. `decide.mjs` 맨 위 상수와 값이 같습니다.
- `xdr/persistence/respond.mjs`: block만 차단 후보(`block-candidates.json`, 만료 60분·근거 경보 번호·`agent` 참고 칸 포함)로 만들고 block·alert를 `xdr/alerts.log`에 한 줄씩 쌓습니다. 규칙의 대상은 출발 주소입니다. 연습 경보가 모두 같은 PC에서 오고 같은 계정이 공격과 정상에 함께 나와서 PC 이름이나 계정으로는 정상 사용자가 막힙니다. 같은 주소의 정상 이벤트가 공격 시도보다 많거나, 주소 형식이 아니거나, 내부·특수 주소면 후보에서 뺍니다. `blockingRule(후보, 주소, 시각)`은 만료 전 규칙만 돌려주는 확인 함수이며 아무 파일도 부르지 않습니다.
- `xdr/persistence/read-alerts.mjs`: 경보에서 시각·주소·계정·수준·설명만 뽑고 비밀값 모양은 가립니다. 확인용이며 `decide.mjs`는 불러오지 않습니다.
- 다시 실행: `npm run xdr:run -- persistence`(성공하면 화면에 아무것도 안 나오고 `xdr/persistence/result.json`을 씁니다), `node xdr/persistence/respond.mjs`(후보·알림), `node xdr/persistence/read-alerts.mjs`(경보 24건 / 뽑은 줄 24줄 일치 확인). `result.json`, `block-candidates.json`, `alerts.log`는 산출물이라 Git에서 제외했습니다. 이 보너스 전용 시험 파일은 만들지 않았습니다.

### 몰래 심어진 프로그램 보너스의 남은 약점 (해소되지 않음)

- **판정기에 연결하지 않았습니다(보류).** 차단 후보는 파일로만 남고 실제 접속 격리는 일어나지 않습니다. 판정기 요청 계약(`docs/DECIDER_REQUEST.md`의 18개 항목)에 출발 주소도 PC 이름도 없고, 경보의 `agent.name`을 계약의 `deviceId`와 이을 근거도 없습니다. 계약에 없는 항목을 만들어 쓰지 않기로 했습니다. 운영 쪽이 계약에 값을 더해야 풀립니다.
- **후보 만료(60분)를 강제하는 곳이 없습니다.** 후보 파일은 `respond.mjs`를 실행할 때마다 새로 쓰고, 만료는 `blockingRule`을 부를 때만 봅니다.
- 시작 프로그램과 예약 작업이 같은 임시 파일을 가리키는 경보(ps-07)는 서로 다른 두 패턴이 함께 맞고 둘 다 경로 근거가 있으면 +0.30을 주는 조합 규칙으로 block됩니다. 이 규칙은 연습 경보에 맞춰 정한 값입니다. ps-04의 확신도는 block 경계인 정확히 0.85입니다.
- 서명 여부와 평소 목록은 경보 설명의 문구에서만 읽습니다(서명을 직접 검사하지 못함). 다른 문구의 경보는 놓치거나 alert로만 남을 수 있습니다. 임시 폴더 경로를 더 의심하는 근거는 시작 폴더 쪽만 ATT&CK 설명에 있고, 서비스·예약 작업 쪽은 연습 경보 문구를 따른 이 모듈의 값입니다.
- 확신도 숫자(0.5, +0.35, +0.05, +0.30)는 이 모듈이 정한 값입니다. ATT&CK도 정하지 않았습니다. 숨긴 예약 작업, 서비스 이름 위장은 근거를 읽지 않아 넣지 않았습니다.
- 같은 주소에서 공격 1건과 정상 1건이면 후보로 남습니다(정상이 더 많을 때만 보호). IPv6 주소는 후보에서 빠집니다(알림 로그에는 남습니다). `alerts.log`는 계속 쌓이고 정리 규칙이 없으며, 다시 실행하면 줄이 중복됩니다.
- 주소 단위 차단뿐이라 주소를 바꾸는 공격과 공용 주소(NAT) 사정은 구분하지 못합니다.
- 시험 자료가 가짜이고 심판 경보의 형식은 이 저장소에서 확인할 수 없습니다.
